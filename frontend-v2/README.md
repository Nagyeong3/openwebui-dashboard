# OpenWebUI Analytics v2

React + TypeScript + Vite로 새로 구축한 프런트엔드입니다. 기존 Streamlit 코드 및 폐쇄망 운영 소스를 대체 설치한 상태가 아닙니다.

## 현재 상태 (2026-10-23)

- 구현 및 로컬 검증 대상: 개요, 사용자/팀/팀장 분석, 토큰 사용량, 운영 업데이트 화면.
- 기본 라이트 + 다크 테마, 모션 감소 설정, 차트 확대/교차 필터, 검색 가능한 종속 조직 필터, URL 상태, 사용자 상세 패널.
- 전체 DB 사용자 명부에 사용량을 연결합니다. 기간 내 사용량이 0이어도 사용자/팀장 전체 순위에서 표시합니다.
- **기본 실행은 합성 데모 데이터**입니다. 실사용자의 이름·조직·DB·키가 포함되어 있지 않습니다.
- API 모드는 신규 `backend_v2` 사용자 API와 연결됩니다. 사용자/팀/팀장 조회, 서버 페이징/검색/정렬, 전체 CSV, 사용자 상세, 수집 오류 상태를 제공합니다. 실제 폐쇄망 데이터 연결은 현장에서 검증해야 합니다.
- API 모드에는 사용자 분석만 표시합니다. 개요/토큰/운영 화면은 데모에 남으며 후속 단계에서 연결합니다.
- 운영 업데이트는 데모에서만 시뮬레이션합니다. 실제 업데이트 작업이나 DB 복사를 실행하지 않습니다.

## 실행

Node.js 22.12 이상 (검증 환경: Node 24), npm이 필요합니다. Node 16에서는 빌드하지 마세요.

```sh
cd frontend-v2
npm ci
npm run dev
```

브라우저에서 터미널에 표시되는 개발 서버 주소로 접속합니다.

```sh
npm test
npm run build
```

`dist/` 전체가 정적 배포 산출물입니다. 화면 폰트, 차트, 아이콘을 함께 번들링하므로 운영 브라우저에서 외부 CDN이 필요하지 않습니다.

## 데이터 및 코드 경계

| 파일 | 책임 |
| --- | --- |
| `src/mock.ts` | 고정된 합성 DB 사용자 및 일별 집계 |
| `src/domain.ts` | 전체 DB 명부 기반 집계, 조직 필터, 0건 순위, CSV |
| `src/api.ts` | API 요청/오류 처리 및 응답 검증 경계 |
| `src/components.tsx` | 검색 셀렉트, KPI, ECharts, 모달/상세 패널 |
| `src/App.tsx` | 4개 화면, URL 상태, 내보내기, 운영 작업 UI |
| `src/styles.css` | 디자인 토큰, 테마, 반응형, 인쇄 |

계약 및 폐쇄망 연결 절차는 [API_CONTRACT.md](../docs/DASHBOARD_V2_API_CONTRACT.md), 확정 요구사항과 검증 기록은 [DASHBOARD_V2.md](../docs/DASHBOARD_V2.md)를 참고하세요.

## 데모 사용 방법

- 차트 막대/도넛/범례 버튼을 클릭하면 조직·카테고리·모델 필터가 적용됩니다. 선택 칩의 × 또는 초기화로 해제합니다.
- 사용자 분석에서 `팀장` → `전체 N명`을 선택하면 0건 팀장까지 조회합니다. 기본 Top 10은 내림차순 10명입니다.
- 질문/토큰 정렬 버튼을 눌러 오름차순으로 바꾸면 0건 사용자부터 확인할 수 있습니다.
- CSV는 현재 페이지의 10행이 아니라 필터에 맞는 전체 사용자 행을 내보냅니다. 팀 보기에서도 사용자별 원본 집계 CSV입니다.
- PNG는 현재 표시 화면, PDF는 브라우저 인쇄입니다. 전체 페이지의 모든 페이징 행을 자동 인쇄하는 기능은 아닙니다.
- 기간/조직/모델/카테고리/현재 화면은 URL로 복원합니다. 테마는 브라우저에 저장합니다.

## 실제 API 연결

```sh
npm run dev:api
# backend_v2 on 127.0.0.1:8011; Vite proxies /api
npm run build:api
```

`npm run build`는 합성 데모, `npm run build:api`는 실제 사용자 API 연결 빌드입니다. `.env.api`에 비밀키는 없습니다. 주소를 바꿀 때만 `VITE_API_BASE_URL`을 사용하며, OpenWebUI 관리자 키/대시보드 키를 VITE 변수에 넣지 않습니다. API 오류 시 데모로 대체하지 않습니다.

- API 엔드포인트: `/api/dashboard/v2/users`, 전체 CSV: `/api/dashboard/v2/users/export`.
- API 모드 진입점: `LiveApp.tsx`, 응답 검증/쿼리: `live-api.ts`. 이전 snapshot decoder는 데모 계약의 기록이며 새 모드에서 사용하지 않습니다.
- 조직/기간/보기/검색/정렬/페이지를 URL에 보존합니다. 실/본부 변경 시 팀과 직급을, 팀 변경 시 직급을 초기화합니다.
- 차트는 필터 전체의 일별 합계와 현재 페이지의 앞 10행입니다. 현재 페이지 차트를 전사 Top 10으로 표시하지 않습니다.
- 전체 CSV는 서버에서 한 번의 캐시 읽기로 생성하며 페이징 제한을 적용하지 않습니다. UTF-8 BOM, 수식 문자열 보호.
- `DASHBOARD_API_TOKEN`을 설정했다면 상단 설정에서 **대시보드 토큰**을 입력합니다. OpenWebUI 관리자 키가 아닙니다. 메모리에서만 유지하며 새로고침하면 지워집니다.
- 마지막 성공 데이터, 수집 미완료/실패 상태, 미매칭 조직을 표시합니다. 최초 수집 전 503은 오류 안내로 표시합니다.
- 토큰/비용/카테고리는 미연결 안내로 표시하고 0으로 대체하지 않습니다.

폐쇄망 실행·검수는 [PHASE5_OFFLINE.md](../docs/PHASE5_OFFLINE.md)를 따릅니다.

## 폐쇄망 배포

1. 인터넷 개발 PC에서 `npm ci`, `npm test`, `npm run build:api`.
2. `dist` 폴더 전체를 승인된 절차로 반입합니다. `assets`의 해시 파일을 선택적으로 복사하면 안 됩니다.
3. 운영 서버의 기존 정적 프런트 폴더를 백업한 뒤 새 `dist` 전체로 교체합니다.
4. 정적 서버가 `index.html`을 제공하도록 설정합니다. API는 같은 origin의 `/api` 경로로 FastAPI에 reverse proxy 하는 구성을 권장합니다.
5. 정적 운영에는 Node/npm/node_modules가 필요 없습니다. 폐쇄망에서 다시 개발·빌드하려면 맞는 Node 버전과 잠금파일에 맞는 의존성 반입이 별도로 필요합니다.
6. 새 백엔드의 `DASHBOARD_FRONTEND_DIR`에 dist 경로를 지정하면 같은 8011 포트에서 화면과 API를 제공합니다. 운영용 외부 접근/인증은 별도 배포 설정이 필요합니다.

실제 API 모드는 공식 OpenWebUI API를 수집한 신규 분석 캐시를 조회합니다. 과거 폐쇄망 API 응답을 다시 제공할 필요는 없습니다.

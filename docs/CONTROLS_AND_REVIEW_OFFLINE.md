# 일시 중단·재개와 분류 확인

2026-10-28 구현. 기존 데이터/토큰/분류 캐시를 그대로 쓰며 정상 v2 작업 DB에 제어·대상 해시·직접 수정 정보를 추가합니다. 기존 결과를 전체 재수집하거나 삭제하지 않습니다. 새 패키지 설치는 없습니다.

## 반입과 실행

1. 진행 중인 작업을 끝내거나 중단하고 Uvicorn을 Ctrl+C로 종료합니다.
2. 기존 backend_v2와 frontend_v2/dist를 백업 후 이번 ZIP의 폴더 전체로 교체합니다. 프런트만 교체하면 제어 API가 없습니다.
3. .env, data, 기존 DB, 실제 CSV와 Conda 환경은 보존합니다. 새 .env.example로 덮어쓰지 않습니다.
4. 기존 명령으로 실행합니다.

```bat
conda activate D:\project\oui-env-v2
cd /d D:\project\oui-dashboard-v2
python -m uvicorn backend_v2.app:create_app --factory --host 127.0.0.1 --port 8011
```

브라우저 Ctrl+F5. 운영 업데이트 버튼은 `업데이트`, 상단 인증 입력/운영 새로고침 버튼이 없어야 합니다. 메뉴에서 아직 구현하지 않은 항목도 숨겼습니다. 실패한 상태 조회에는 `다시 불러오기`가 나타납니다.

## 질문 분류

- `분류 시작`: 시작 당시 전체 미처리 질문을 내부적으로 나눠 자동 처리.
- `20개 먼저 분류`: 최대 min(20, CATEGORY_LLM_MAX_QUESTIONS)개.
- `일시 중단`: 현재 모델 요청 결과를 저장한 후 멈춤. 대상은 해시로 기록되며 원문은 저장하지 않습니다.
- `계속하기`: 같은 대상 집합의 미완료 질문만 처리. 새 질문이 들어와도 소량 확인 대상이 늘어나지 않습니다. 이미 완료한 요청의 결과를 재사용합니다.
- `중단`: 해당 실행을 종료. 완료한 결과는 유지. 다음 `분류 시작`은 현재 snapshot의 미처리 질문을 새로 찾습니다.
- 서버가 종료돼 작업이 중단된 경우 약10분 후 잠금 만료 상태에서 계속하기 가능. CSV/모델/분류 프로필이 바뀌면 기존 실행은 중단 후 새로 시작합니다.

외부 모델이 요청을 처리한 직후 서버가 응답/결과를 저장하기 전에 강제 종료된 경우, 그 응답을 복구할 수 없어 해당 요청은 재전송될 수 있습니다. 정확히 한 번의 과금을 보장하지 않습니다.

## 운영 업데이트

체크박스에서 데이터·토큰·질문 분류 중 실행할 항목을 선택합니다. 기본은 셋 모두이며 한 번 클릭해 순서대로 처리합니다. `전체 업데이트`는 선택한 원천의 전체 이력을 재대조하므로 평소에는 업데이트를 사용합니다.

- `일시 중단`: API 요청 경계에서 멈춤. 이미 전송한 요청을 회수하지 않습니다.
- 데이터/토큰 수집의 미완성 staging은 공개하지 않으며 마지막 정상본을 유지합니다. 계속할 때 **미완료 원천 단계의 조회를 처음부터 다시 확인**합니다. 완료한 앞 단계는 반복하지 않습니다. 고정 API cursor/snapshot을 제공하지 않는 원천에서 오래된 offset을 그대로 재개해 누락시키지 않기 위한 처리입니다.
- 질문 분류는 완료 결과와 대상별 체크포인트로 이어 처리합니다.
- `중단`: 실행을 종료하고 이후 단계도 중단으로 표시. 이미 정상 공개한 앞 단계와 저장한 분류는 유지됩니다.
- `실패 항목 다시 실행`/실행 내역의 `재시도`: 실패·일부 완료·중단된 항목과 그 실패로 건너뛴 후속 항목만 새 실행으로 만듭니다. 완료한 항목은 선택하지 않습니다.
- 일시 중단된 운영 작업이 있으면 새 작업 대신 계속하기 또는 중단을 선택합니다.
- 월1회 실행도 마지막 성공 시점 이후 전체 구간과 중복 여유를 조회합니다. 변경분 조회 기준은 원천별로 독립적입니다.

## 기타 질문 확인과 수정

카테고리 화면 `기타만 보기` → 해당 질문의 `확인·수정`을 누릅니다. OpenWebUI의 해당 채팅 메시지 API에서 원문을 그때 조회하여 표시합니다. 사용자 전체 이력을 처음부터 읽지 않습니다. 로컬 분류 DB에는 원문을 저장하지 않고 응답도 no-store로 제공합니다. 조회가 오래 걸릴 수 있고, 원문이 변경/삭제되면 데이터 업데이트가 필요합니다.

카테고리를 선택하고 저장하면 **그 질문만** 수정합니다. 텍스트가 같은 다른 사용자의 질문을 한꺼번에 바꾸지 않습니다. 직접 수정은 모델 변경 이후에도 질문 해시가 같고 해당 카테고리가 활성화돼 있으면 우선 적용합니다. 질문 내용이 바뀌거나 카테고리가 삭제/비활성화되면 이전 수정을 자동 적용하지 않습니다. 새로운 카테고리 정의 추가는 기존 CSV에서 관리합니다.

실행 이력 내보내기는 추가하지 않았습니다. 기존 사용자/토큰/리포트 CSV 기능은 유지합니다.

## 범례와 글자

개요와 카테고리 화면 모두 도넛 왼쪽 / 전체 범례 오른쪽. 범례를 페이지로 나누지 않습니다. 좁은 화면에서는 아래로 배치합니다. 본문·버튼·표·보조 글자·차트에 14px 이상을 적용했습니다. 정상 화면에서 내부 처리 방식/개발 예정 문구는 제거하고 결과·시각·상태 위주로 보여줍니다.

## 기존 인증 설정

상단의 대시보드 토큰 버튼/입력창은 제거했습니다. `DASHBOARD_API_TOKEN`이 비어 있으면 로그인 없이 사용합니다. 기존에 값이 설정된 환경은 별도 로그인 화면에서 **기존 값**을 접속 암호로 입력합니다. 값 자체를 바꾸거나 프런트 빌드에 넣지 않습니다. HttpOnly/SameSite 쿠키로8시간 유지하며, CLI의 Bearer 헤더는 계속 지원합니다. 기존 API 보안을 화면 변경 때문에 자동 해제하지 않습니다. 현재 배포는 같은 origin의 FastAPI 정적 제공을 기준으로 합니다.

## 검수

1. 범례가 한 번에 모두 보임. 글자를 줄이지 않고 작은 화면에서 재배치.
2. 분류를 몇 건 진행 후 일시 중단 → 새로고침/서버 재실행 → 계속하기. 완료 질문 재호출 없음.
3. 운영 중 데이터/토큰 단계에서 일시 중단. 이전 정상 캐시 유지, 계속하면 앞서 완료한 단계는 실행하지 않음.
4. 중단하면 이후 단계가 진행되지 않음.
5. 토큰 실패 후 재시도 시 데이터 수집을 반복하지 않음.
6. 기타 한 질문을 수정하면 해당 질문과 통계만 갱신. 같은 텍스트 다른 질문 유지.
7. 기존 인증 설정이 있는 환경에서 로그인 전 API401, 로그인 후 정상, 상단 토큰 버튼 없음.

원문·키·실제 직원 데이터를 반출하지 않고 현장에서 확인합니다. 실제 Windows 브라우저와 외부 모델 연동은 현장 검수 대상입니다.

상태조회는 실행 중 약3초, 대기 중 약30초 간격으로 자동 반영합니다. 원천 API나 모델을 호출하지 않는 상태 조회이며 새로고침 버튼은 없습니다.

로컬 검증: 백엔드103 / 프런트30 테스트, TypeScript/API 빌드 통과. 자동 검증은 합성 데이터 기반이며 실제 폐쇄망 모델과 Windows 브라우저 시각/상호작용 검수는 미완료.
